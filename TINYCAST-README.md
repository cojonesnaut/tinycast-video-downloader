# Video Downloader for Tinycast on macOS

**Tested with Tinycast Beta 0.12.1.**

This is a Tinycast-specific rebuild of vimtor's Video Downloader. The compiled `index.js`, manifest and assets are ready to import; Node.js is not required to run it.

## Use

In Tinycast, open **Download Video**. The suggested shortcut is **⌘⌥D**. Tinycast stores shortcuts in its own settings, and extensions can't ship one, so set it once under Tinycast → Settings → Extensions → Video Downloader → Download Video with the shortcut recorder. It is kept when you reinstall over the existing folder and removed if you uninstall the extension. Paste a complete link into the **Video URL** field (not the launcher search field). The Status row shows lookup progress, the video title, or an error. Choose a format, then press **Return** to download. A metadata lookup is not required before downloading.

Formats: MP4 video (default), original format at the highest resolution, or MP3 audio. When MP4 is selected, a **Resolution** dropdown offers Highest (4K), 1440p, 1080p or 720p. When the video has dubbed or auto-dubbed audio (for example on YouTube), an **Audio Language** dropdown lists every audio language after the lookup finishes. It defaults to the original track and works for MP4, original format and MP3. A dubbed download gets the language code in its file name (for example “Title [id].es.mp4”), so it never replaces the original-language file. It can also run beside an original-language download of the same video. If the chosen language isn't available at download time, the original audio is used. MP4 selection prioritizes resolution and frame rate, then prefers MP4 video and M4A audio. Highest (default) selects 4K/8K when offered by the source, without upscaling lower-resolution video. A resolution limit picks the largest stream at or below it; if the source has nothing that small, the closest larger stream is used. Limits apply to the shorter side, so portrait videos are handled the same way. If the highest-resolution stream uses another container, it is remuxed to MP4 without downscaling. MP4 may contain AV1 or VP9 depending on the source. Playlist downloading is optional. You can close the command while downloading: the download keeps running, and reopening **Download Video** shows its progress again, with Pause and Stop still working. Pressing Download for a video that is already downloading shows that download instead of starting a second copy, since two runs would overwrite each other's partial files. The Glass sound plays on success even if the command was closed. While downloading, the command shows a details panel: URL, Status, File size, Downloaded (with the percentage), Transfer rate, Time left, Resume capability and Save to, above a rounded progress bar in your macOS accent colour. The panel starts with the video title, at the same size as the rows. The panel has no background of its own, so Tinycast's liquid-glass panel shows through, and its text follows light or dark appearance. Return pauses or resumes, ⌘. cancels, and **Close When Completed** (⌘⇧W) is a toggle in Actions. Numbers follow your region's decimal separator. When the download ends, a finish screen appears, also on the glass: a green check, a bold “Download completed”, the file name, and Size, Location, URL and Finished (for example “Oct 24, 2026 at 14:59”), with **Open**, **Show in Finder** and **Close** in Actions. A failure shows a red badge with the error line, **Try Again** and **Copy Error**. A cancelled download shows a grey badge and **Resume**, which continues from the partial files. A separate animated downloading toast is intentionally not shown, so no stale “Keep this command open” strip remains after completion. Sites such as YouTube deliver video and audio as separate streams. yt-dlp's sizes for both are read before the download starts, so the window shows one progress bar, byte count and time left for the whole video instead of restarting for the audio. If a site doesn't report the sizes, each stream shows its own progress. In playlists, each item has its own progress. Processing is shown separately; only confirmed completion turns the bar green at 100% and plays the macOS Glass notification sound. On success, **Show Download in Finder** is available in Actions. Choose **New Download** to return to the form. Failures show a red bar and an error with no completion sound.

The extension detects yt-dlp, ffmpeg and ffprobe in Homebrew's Apple Silicon and Intel locations, or from the executable paths in extension preferences. The download directory defaults to `~/Downloads`. `ffprobe` is included with ffmpeg. Browser cookies are used only when the existing cookie preference is enabled. yt-dlp runs as part of Tinycast, so macOS checks Tinycast's permissions: Safari cookies need Full Disk Access for Tinycast, and Chromium browsers such as Brave or Chrome may need Tinycast to be allowed to access data from other apps, plus a one-time Keychain prompt. If the cookies can't be read, the form shows a **Cookies** note explaining why, and the lookup and download continue without cookies instead of failing. To test the setting, choose **Check Browser Cookies** (⌘⇧K) in Download Video. It reads the browser's cookies inside Tinycast, so the result reflects Tinycast's real permissions. It reports how many cookies were read, whether you're signed in to YouTube in that browser, and any fix needed. When the fix is a permission, **Open Privacy Settings** opens System Settings → Privacy & Security. The check's temporary cookie file is deleted straight away. **Force IPv4** adds yt-dlp's `--force-ipv4` to every lookup, download and transcript request. Clipboard autofill is supported; the upstream selected-text autofill preference is not used by this Tinycast interface. Browser extension support was removed because Tinycast has no browser extension.

## Extract Transcript

Open **Extract Transcript**, paste a video URL, and choose **Load Caption Languages**. Select a published or automatic caption track, optionally enable timestamps, then choose **Extract Transcript** (⌘Return in current Tinycast Beta). The transcript appears in a preview with **Copy Transcript**, **Save as Markdown**, **Save as Text**, and **Show/Hide Timestamps** actions. Saved transcripts go to the configured download folder with a unique filename.

This extracts existing captions, including automatic captions and translated tracks when exposed by the site. It does not perform speech recognition on videos without captions, and needs no Raycast AI service. It reuses the yt-dlp/ffmpeg paths and opt-in browser-cookie preferences. If the configured browser session exposes no captions or fails, the command retries publicly and keeps that public mode for subtitle extraction. Temporary subtitle files are isolated per extraction and cleaned up afterward. Meaningful parenthetical and bracketed text is preserved; rolling caption overlap is removed.

Verified with a real YouTube automatic-caption extraction, plus Tinycast runtime tests for the language picker, preview, timestamp toggle, and Markdown/text exports.

## Import or rebuild

Tinycast → Settings → Extensions → Install → Add Folder → select **video-downloader**.

To rebuild, install Node.js with npm and run `Build.command`, or:

```sh
npm install --ignore-scripts
npm run build
```

For locked dependencies: `pnpm install --frozen-lockfile --ignore-scripts && pnpm run build`.

## Compatibility changes

The Tinycast entry point is `src/index.tsx`, the file Raycast's `ray build` uses for the Download Video command. It uses controlled React form fields and the supported `execFile` process API, avoiding the original Raycast utility hooks and execa's unsupported Node APIs. Format choices are always available. Lookup errors, missing binaries, failed downloads and saved paths are visible. Live yt-dlp progress is written to a unique temporary log and sampled every 250 ms, since Tinycast buffers process callbacks. Both screens are small transparent images of text and flat shapes (about 4 KB, 2.6 ms to decode), shown in a Detail view rather than a Grid tile so no selection plate covers the glass. The progress panel is redrawn at most once a second (state changes such as Paused, Processing and Finished show immediately). The earlier Downie-style card embedded a thumbnail and took 50–80 ms to decode per update. That cost about 70% CPU and 174 MB at four updates a second, and about 8% CPU and 109 MB at one a second. Temporary logs are removed when the download completes or fails. Unknown totals show a preparing state until yt-dlp reports a percentage. Transfer statistics come from yt-dlp, and unknown values are omitted rather than guessed. User yt-dlp config files are ignored so external options cannot suppress downloads or change machine-readable output.

The original Raycast screen is preserved in `src/raycast-index.tsx` for reference and is not built. Tinycast's **Install from GitHub** runs `ray build`, which type-checks the whole project with `tsc` before building. The project passes that check, so installing straight from the repository works. The upstream AI tool bundles are included, but Tinycast's folder importer installs only the main UI command.

## Verification

Tested against the JavaScript runtime shipped in the installed Tinycast app with real yt-dlp and ffmpeg: pasting a YouTube link loaded metadata; form submission saved MP3 and MP4 files; ffprobe confirmed video and audio in the MP4. The installed app was also checked directly for URL lookup and downloading. A throttled real YouTube download through the installed runtime verified intermediate percentage updates, green 100% completion, and the afplay notification command. Parser checks cover unknown totals, separate transfers, processing, failure colors, byte counts, speeds, remaining time and escaped titles. A real runtime download verified that no download toast is created. The progress panel, pause/resume, Close When Completed, and the completed, failed and cancelled screens were tested with real downloads, and the panel was compared pixel by pixel with its reference design. Format-selection tests prefer 4K MP4 over lower-resolution MP4 and retain 4K resolution when remuxing is needed. Closing the command mid-download was tested with the supervisor left running and with it killed: the reopened command reattached, Pause suspended yt-dlp, Resume continued it, the file completed at its full size, and pressing Download again for the same video attached instead of starting a duplicate.

## Pause and stop downloads

While downloading, use Pause / Resume in Actions (Command-P), or Cancel Download (Command-period). Pause also suspends FFmpeg processing. A paused download stays paused if you close the command. Cancel terminates the download and any processing, keeps partial files for a later retry, and does not play the completion sound. The progress bar stays still while paused.
